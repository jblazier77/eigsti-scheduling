# First connected application screens

## Current scope

The Next.js application now includes standalone password sign-in, sign-out, live account checks, My Jobs/All Jobs for PMs, read-only assigned jobs for other operational roles, three-field job creation, and authorized job details with call/text/directions. PMs can edit title, customer, phone, address, scope and access/preparation notes at /jobs/[id]/edit. Only changed fields are saved; helpers/leads cannot use the edit page or action. Optional notes can be cleared and multiline text is preserved. No new database migration is required. The Phase 0 memory-only prototype is separate (`npm run preview`). No scheduling features are connected yet. Contacts, private file uploads, invites/recovery and phone user administration remain Phase 1 work.

## Security and save behavior

Session tokens are in HttpOnly, SameSite=Lax cookies. Cookies are Secure in production builds/environments; use the development server for local HTTP testing. Proxy refreshes sessions; pages and actions verify identity through Auth and an active live app profile. Server Actions apply their own role checks; showing a PM form does not grant its permissions. Direct API jobs route remains Bearer-token-only.

The job form uses controlled fields and one request UUID per form. An uncertain save preserves the details, prevents changing that payload, and offers retry with the same UUID. A confirmed save navigates to the returned job. The database command atomically creates job, default work and history. Actual dropped-connection/browser checks and simultaneous-user retry tests remain pending.

## Additional contacts workflow

On a job, the existing customer contact remains separate. The Additional job contacts section can contain a spouse, site contact or subcontractor for that specific job. PMs see Add contact/Edit; authorized leads/helpers see read-only details and call/text/email links. This does not connect to Google or send any automatic messages. A company-wide trade directory and subcontractor visits are future phases.

Only the contact name is required. Other fields are relationship/trade, phone, email and shared notes. Use synthetic details only in test. Creation retains one request UUID and locks values after an uncertain save so retry cannot duplicate the contact. Edits send only fields changed from the original form. Failed saves retain values, cancel confirms discarding edits, and removal requires an explicit confirmation panel and archives the row/history. Up to 100 active contacts per job.
